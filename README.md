# 三环 2×2×2 魔方

原生 TypeScript + SVG 的角块交互模块，供 Astro/Starlight 博客嵌入，不是独立生产网站。运行时没有前端框架、后端或三维渲染依赖。本地旧投影实验不属于模块发布内容。

仓库：<https://github.com/Hyperbolica-dev/cube> · [中文版体验](https://hyperbolica-dev.github.io/zh/fun/cube/) · [English demo](https://hyperbolica-dev.github.io/fun/cube/)

新协作者或 LLM 从 [协作与接入指引](CONTRIBUTING.md) 开始。各自使用任务分支，通过 PR 交换成果与当前判断；Cube 合并不会自动更新博客的子模块引用。

## 博客集成

宿主读取纯元数据 `src/module.ts` 的 `moduleMeta`：`id: 'cube'`、语言 `en` / `zh-CN`，以及两种语言的 `title` / `description`。此入口不引入 DOM、样式或 Astro。

在宿主 Astro 页面导入组件（相对路径按实际仓库位置调整）：

```astro
---
import Cube from '../../cube/src/components/cube/Cube.astro';
---

<Cube language="en" />
<Cube language="zh-CN" />
```

`language` 必填，类型为 `'en' | 'zh-CN'`。组件不需要路由或 `pagePath`。宿主负责页面标题、导航、主题和布局；组件只输出交互区及禁用 JavaScript 时的本地化提示。所有 UI 文案、SVG 无障碍标签、状态、颜色名称、操作说明和摘要均有完整的两种语言版本。

组件继承宿主字体与 Starlight `--sl-*` 变量，包括 `--sl-color-text`、`--sl-color-white`、`--sl-color-bg`、`--sl-color-bg-sidebar`、`--sl-color-bg-nav`、边框及强调色。`src/style.css` 的全部选择器限定在 `.cube-app` 下；图与操作面板根据模块容器宽度而不是视口宽度堆叠。六种物理角块颜色不受主题影响。生产入口不读取主题存储，不引入本地预览外壳，也不依赖同级博客源码。

`src/main.ts` 导出低层入口 `mountCube(root, { language })`，返回幂等 `destroy()`。直接使用时还应导入 `src/style.css`。同一根节点重复挂载返回原销毁函数；变更语言需先销毁再挂载。UI 模板只有 `src/ui.ts` 一个所有者，Astro 服务端输出与本地预览复用它。查询、状态、按钮和键盘事件限定在实例内；只有聚焦模块及其非编辑控件时才处理 F/U/R。指针操作先聚焦模块。多个实例互不影响。

Astro 包装使用模块专用的自定义元素连接/断开回调挂载和销毁，支持客户端导航及重新连接。销毁会释放指针捕获、移除事件监听、取消动画帧、结束待处理的手势/动画，并阻止异步续体继续修改已销毁实例。窗口失焦监听仅用于取消当前实例手势，随实例一起移除。

Astro 是可选宿主 peer dependency（7.2.10 及兼容的 7.x）；本地 Vite 预览不需要安装 Astro，也不把本仓库变成独立 Astro 网站。组件的 Astro 类型检查由宿主的 Astro 检查命令承担。

## 本地预览与验证

需要 Node.js 20.19+ 或 22.12+，以及支持 `Promise.withResolvers()` 和容器查询的现代浏览器。

```sh
npm install
npm run dev
npm run quality
npm run build
npm run preview
```

`dev` 地址由终端输出。`index.html`、`src/preview.ts` 和 `src/preview.css` 仅是本地预览：提供语言切换与不保存偏好的浅色/深色/系统主题令牌，不进入生产组件的导入图。`build` 生成该预览的 `dist/`，不是博客部署产物；博客使用组件源码自行构建。不要提交 `node_modules/`、`dist/`。

## 操作

- 直接点按圆周或圆环标签：左键顺时针，右键逆时针，对应 F、U、R 及其逆操作，合计六种操作；圆环上禁用浏览器右键菜单。
- 左右键均可自由顺拖、逆拖，并可在一次按住期间中途反向、连续移动任意步数。方向取决于实际手势，而不是鼠标按键；只有不拖动的点按保留左顺、右逆。
- 拖动按实际圆弧和非等距槽位计算进度：被抓取处最近的角块作为锚点，跨过一个槽位表示一步，绕一整圈表示四步，不再固定按 90° 换算一步。
- 松开时直接吸附到最近的合法槽位状态，不补播动画；不足半步回到原位，越过半步吸附到下一槽位。历史记录吸附后的净步数及方向，连续多步可逐步撤销。
- 拖动期间只显示预览，不提前提交逻辑状态和历史。鼠标移出 SVG 后松开仍会吸附；指针取消、捕获丢失或窗口失焦则恢复整个手势前的状态。
- 六个按钮保留为替代入口；圆环标签支持 Enter 正转、Shift + Enter 逆转，空格同样适用。
- 先聚焦交互区再按 F / U / R 执行正转，Shift + 对应键执行逆转；输入框、选择框和可编辑内容不拦截快捷键。
- 撤销沿历史逆向执行一步；随机打乱执行 20 个四分之一转，相邻操作不选同一个面，不保证均匀随机状态。
- 重置直接返回还原态，不是求解当前状态。
- 可隐藏身份字母，单独观察三色方向；可关闭动画，系统也遵循减少动态效果偏好。
- 拖动及动画过程中锁定其他转动、撤销、打乱和重置，避免状态与画面交错。

## 数学约定

正 x 为右面蓝色，正 y 为上面白色，正 z 为前面红色；负方向分别为绿、黄、橙。正转为从该真实魔方面外看顺时针 90°。

| 槽位 / 还原角块 | 真实位置 | 三色组合 |
|---|---|---|
| A | 前上右 | 红白蓝 |
| B | 后上右 | 橙白蓝 |
| C | 前下右 | 红黄蓝 |
| D | 后下右 | 橙黄蓝 |
| E | 前上左 | 红白绿 |
| F | 后上左 | 橙白绿 |
| G | 前下左 | 红黄绿 |
| H | 后下左 | 橙黄绿 |

位置槽位与角块身份分开保存。H 的位置及取向固定，角块取向和模 3 为零。允许七个活动角块的任意排列，不施加错误的偶排列限制。

每个槽位的局部有序面法向量具有相同手性（行列式 -1）。角块颜色顺序由还原位置的局部坐标系定义；取向 o 表示其颜色索引 0 当前落在目标槽位的面方向索引 o。F/U/R 的置换及取向增量直接由整数三维旋转推导，而不是按视觉效果指定。

正向循环（从左到右，最后回到第一个）：

- α / F：G → E → A → C → G。
- β / U：E → F → B → A → E。
- γ / R：A → B → D → C → A。

`src/layout.ts` 定义等大三环、固定槽位及各槽位还原朝向。G、F 位于左右圆环各自沿三角形对称轴的外上方圆周交点；它们与中央 A 分别位于对应圆的一条直径两端。三个环的槽位并非等角间隔，公转沿实际圆弧插值，不将四块整体转动 90°。

图案显示角为槽位基准角加 `120° × o`，颜色有序排列从不镜像；身份文字不跟随图案旋转。动画只连接合法离散状态，中间帧不定义额外魔方状态。

## 文件与验证

- `src/module.ts`：无副作用的模块 ID、支持语言与双语元数据。
- `src/components/cube/Cube.astro`：宿主组件、服务端 UI 与挂载/销毁生命周期。
- `src/ui.ts`：唯一 UI 模板及完整的英中双语文案。
- `src/main.ts`：根节点作用域内的 `mountCube`、SVG 显示、连续拖动、历史和动画。
- `src/style.css`：仅作用于模块的 Starlight 令牌样式与容器查询。
- `src/cube.ts`：角块状态、物理坐标、操作表与六种不可变颜色。
- `src/layout.ts`：圆环及槽位几何，不参与魔方代数规则。
- `src/preview.ts` / `src/preview.css` / `index.html`：开发预览，不随组件导入。
- `scripts/verify.ts`：操作阶数及逆操作、非法状态边界、10,000 步独立三维贴纸法向量对照、圆弧与对称轴约束、完整状态空间遍历；模型文件路径未移动。

`npm run quality` 执行严格类型检查和上述验证。完整遍历使用排列与取向的紧凑编码，确认仅用 F/U/R 可达恰好 `7! × 3⁶ = 3,674,160` 个合法状态；穷举不会在页面启动时运行。

GitHub Actions 只验证模型、类型并构建开发预览，不部署独立站点。博客固定引用模块提交，再统一构建、部署博客站点。

- [准备表](docs/solving-setup-tables.md)、[取向识别表](docs/solving-orientation-reference.md)、[稳定子修正表](docs/solving-stabilizer-tables.md)：程序生成的实际操作参考。
- `research/local-operations.json`：精选操作数据库；其余 `research/*.json` 保存搜索与验证证据。

```sh
npm run research         # 有界搜索、生成数据/操作表并正式重放验证
npm run research:verify  # 不重新搜索，仅检查数据与模型、作用和程序的一致性
```

研究命令建议 Node.js 22.13+；本次在 Linux / Node.js 24.18.0 上验证，稳定子脚本用 `/proc/self/status` 记录内存。统一运行器硬上限 600 秒，候选深度、数量、状态与内存另有边界。正常 `quality` / `build` 不运行这些研究搜索，也不将数据库或求解流程集成 UI。`scripts/research/codec.ts` 仅复用现有验证器的排列/取向编码，不维护另一套魔方规则。
